# Контрольные вопросы — лабораторная №3

## Веб-сервис

Веб-сервис — программный интерфейс, доступный по сети и позволяющий приложениям обмениваться данными. В этой работе клиент отправляет HTTP-запросы, сервер выполняет бизнес-логику и возвращает JSON.

## REST и RPC

REST описывает ресурсы URL-адресами и использует смысл стандартных HTTP-методов: `GET` читает, `POST` создаёт или выполняет команду, `PUT` заменяет/переводит ресурс в заданное состояние, `DELETE` удаляет. REST stateless: каждый запрос содержит всё необходимое для обработки.

RPC моделирует удалённый вызов функции: адрес часто содержит действие, например `/publishMaterial`. В REST действие выражают методом и ресурсом: `PUT /api/insulation-materials/8/publish`. RPC удобен для команд, REST — для единообразной работы с ресурсами.

## Методы и заголовки HTTP

- `GET` — безопасное чтение; `HEAD` — только заголовки; `POST` — создание/команда; `PUT` — полное или идемпотентное изменение; `PATCH` — частичное изменение; `DELETE` — удаление; `OPTIONS` — поддерживаемые возможности и CORS.
- `Content-Type` описывает тело запроса (`application/json`, `multipart/form-data`), `Accept` — желаемый формат ответа, `Authorization` — учётные данные, `Host` — узел, `Origin` — источник CORS, `Cache-Control` — кэширование, `Content-Length` — длина тела.
- Важные коды: `200`, `201`, `204`, `400`, `404`, `409`, `500`, `503`.

## Версии HTTP

- HTTP/1.0 обычно создавал отдельное TCP-соединение на запрос.
- HTTP/1.1 использует постоянные соединения и pipelining, но страдает блокировкой очереди на уровне приложения.
- HTTP/2 передаёт мультиплексированные бинарные потоки в одном TCP-соединении и сжимает заголовки.
- HTTP/3 работает поверх QUIC/UDP, быстрее устанавливает защищённое соединение и устраняет межпотоковую блокировку TCP.

## HTTPS

HTTPS — HTTP поверх TLS. TLS проверяет сертификат сервера, согласует ключи, шифрует трафик и контролирует целостность. Он защищает данные в пути, но не исправляет уязвимости самого приложения.

## OSI и ISO

ISO — международная организация по стандартизации; OSI — разработанная ею эталонная модель сетевого взаимодействия из семи уровней: физический, канальный, сетевой, транспортный, сеансовый, представления, прикладной. HTTP относится к прикладному уровню, TLS обычно связывают с уровнями представления/сеансовым, TCP и UDP — с транспортным, IP — с сетевым, Ethernet/Wi‑Fi — с канальным и физическим.
